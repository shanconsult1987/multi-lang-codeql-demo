# Reporting a Vulnerability

We take security vulnerabilities seriously.

Please DO NOT create public GitHub issues for security vulnerabilities.

Instead, report vulnerabilities privately using one of the following methods:

## Preferred Method (Recommended)

Use GitHub Private Vulnerability Reporting:

Security → Advisories → Report a Vulnerability

## Alternative Contact

Email:
security@company.com

PGP Key:
https://company.com/security/pgp-key.asc

---

# What to Include in a Report

Please include:

- Description of the issue
- Steps to reproduce
- Proof-of-concept (if available)
- Impact assessment
- Affected versions
- Suggested remediation (optional)

Helpful information:

- Logs
- Screenshots
- Stack traces
- Exploit details
- CVE references

# Coordinated Disclosure Policy

We follow responsible disclosure practices.

Please:

- Allow us reasonable time to investigate and remediate
- Avoid public disclosure before a fix is available
- Avoid accessing or modifying user data
- Avoid service disruption during testing

We commit to:

- Acknowledge reports promptly
- Provide regular updates
- Credit researchers where appropriate
- Publish advisories responsibly

---

# Security Update Process

Security fixes may include:

- GitHub Security Advisories (GHSA)
- CVE publication
- Dependabot advisories
- Emergency patch releases

Security updates are prioritized based on:

- CVSS score
- Exploitability
- Business impact
- Exposure level

# Security Best Practices

We recommend users:

- Keep dependencies updated
- Enable MFA on GitHub accounts
- Rotate credentials regularly
- Monitor Dependabot alerts
- Follow least privilege principles

---

# Safe Harbor

Security research conducted in good faith under this policy will not result in legal action from this organization.

Activities outside this policy may still be subject to investigation.
